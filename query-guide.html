Why corpus documentation matters

A query can run successfully and still count the wrong thing. In N1904, a lemma can be recorded on a word, a phrase and a subphrase. Counting every annotation as another word would change the apparent vocabulary of the text. The documentation helps you decide which records count as evidence for your question.

Use the feature pages to check where a value occurs, the structure browser to choose a unit of context, and the source metadata to check what was annotated. The worked queries below demonstrate the difference. Jump to examples from the N1904 tutorial notebooks.

Start with the annotated unit

In a Context-Fabric search template, a node line names the type to match. Feature constraints on that line apply to the same node. In the Doc4CF structure browser, a “valid on” link means the feature was observed on at least one node of that type. Use the feature page to inspect coverage and the spelling of values. Its frequency table summarizes all populated types together; multiple constraints still need to be tested together.

In N1904, sp (part of speech) and tense occur on words, phrases and subphrases. To count lexical occurrences, choose word. The tense value in this corpus is aorist. Substituting aor in the working query below gave zero matches. Inspect sp · Inspect tense

Run these examples in Python with Context-Fabric 0.5.8 and N1904 TF 1.0.0. Replace the path with your local corpus directory.

from cfabric.core import Fabric

api = Fabric(locations="N1904/tf/1.0.0").load("sp tense frame")
verbs = api.S.search("word sp=verb tense=aorist")
print(sum(1 for _ in verbs))  # 11803

A search template selects combinations of node IDs. A rendering template on the Text & encoding page instead specifies how to display a node as text. Context-Fabric search-pattern tutorial

Connect the match to the unit you want to report

verse sp=verb asks for a verse node carrying that value. It returned zero results in N1904. Indenting a word under a verse expresses containment in the corpus’s slots. It does not require a direct parent edge. The diagram’s large-to-small layout suggests types to investigate; it cannot establish that two particular nodes enclose one another.

query = "verse\n  word sp=verb tense=aorist"
hits = list(api.S.search(query))
print(len(hits))                        # 11803 verse–word pairs
print(len({v for v, w in hits}))         # 5556 distinct verses

Each result contains a verse ID and a word ID in template order. A verse with three matching words contributes three pairs, so count distinct verse IDs when the question is “how many verses?” Search API and return types

Follow an annotated edge when position is insufficient

A word sharing a verse with a verb may have no recorded link to that verb. To find words connected by the N1904 frame annotation, inspect its feature page. Applies to identifies source types; Points to identifies destination types. Here both are words. The Doc4CF graph summarizes applicability at type level; the query follows actual edges between individual word IDs. Inspect frame

query = """pred:word sp=verb
arg:word
pred -frame> arg"""
pairs = list(api.S.search(query))
print(len(pairs))  # 43893 directed pairs

The names pred and arg identify the two template lines. The arrow follows an outgoing edge from the first word to the second. To select an edge label, examine the outgoing target–value pairs. For example, node 10 has a link to node 9 labeled A0 and to node 12 labeled A1.

a1_pairs = [(n, target) for (n,) in api.S.search("word sp=verb")
            for target, value in api.E.frame.f(n) if value == "A1"]
print(len(a1_pairs))  # 15570

On the compiled N1904 corpus with version 0.5.8, search rejected the inline value filter -frame=A1> even though the edge API returned the stored labels. The two-step example above was tested on that configuration. Context-Fabric relation definitions

What changes when you know the N1904 dataset?

These examples adapt research questions from the CenterBLC Text-Fabric tutorial notebooks. The counts below were checked independently with Context-Fabric 0.5.8 on the base N1904 TF 1.0.0 corpus.

Count lexical occurrences at the word level

A hapax legomenon is a word occurring just once in the chosen text. The notebook measures this by lemma. Counting the nonempty lemma values on word nodes gives 1,927 lemmas occurring once. Pool the lemma annotations across every node type and the same frequency test returns zero. Phrases and subphrases also carry the feature; their annotations can repeat a lemma without adding another word to the text. Lemma coverage · Hapax notebook

from collections import Counter
from cfabric.core import Fabric

api = Fabric(locations="N1904/tf/1.0.0").load("lemma ln")
words = api.F.otype.s("word")
counts = Counter(api.F.lemma.v(w) for w in words)
print(sum(n == 1 for lemma, n in counts.items() if lemma))  # 1927

Choose the context window before measuring co-occurrence

The Agape notebook starts with occurrences of ἀγάπη, finds their enclosing verses, then gathers words in each distinct verse. We found 116 word occurrences in 106 verses. Expanding all 116 hits individually would count the context of a verse repeatedly whenever the lemma appears there more than once. A verse window measures shared passage context; a question about grammatical arguments calls for an annotated relation such as frame. Agape notebook

Decide which boundaries a sequence may cross

The n-gram notebook builds sequences from the ordered words of each chapter. For a three-word sequence, that permits crossing a verse boundary inside a chapter. Resetting at each verse instead changes the number of available windows from 137,259 to 121,891. These are counts of positions at which a trigram occurs, including repetitions. The choice matters even before selecting a particular sequence or comparing its frequency. N-gram notebook

def trigram_windows(unit):
    return sum(max(0, len(api.L.d(n, "word")) - 2)
               for n in api.F.otype.s(unit))

print(trigram_windows("chapter"), trigram_windows("verse"))
# 137259 121891

Distinguish a stored field from a code within that field

A word’s Louw–Nida field can hold several space-separated codes. Searching word ln=49.5 found 7 words whose entire field equals that code. Testing membership after splitting the field found 13 words. Use equality to study exclusive assignment; use membership to include words also assigned other codes. A loose substring search can pick up longer codes. Louw–Nida feature · Louw–Nida notebook

exact = sum(1 for _ in api.S.search("word ln=49.5"))
member = sum("49.5" in (api.F.ln.v(w) or "").split() for w in words)
print(exact, member)  # 7 13

Recheck the schema when switching corpora

Dead Sea Scrolls 2.0.4. Here sp was observed only on words. With that feature loaded, word sp=verb matched 58,873 words; phrase sp=verb matched none. An identical feature name can have different coverage across corpora. DSS part-of-speech coverage

Old Babylonian 1.0.6. The cuneiform feature symu occurs on both signs and words. With that feature loaded, sign symu=𒀀 matched 11,708 sign nodes; word symu=𒀀 matched 61 word nodes. Both queries work. The research question determines which unit to count. Old Babylonian sign and word coverage
