How the examples were documented

All three sites use the same Doc4CF generator and begin with deterministic measurements from the corpus. They differ in how much model-assisted interpretation is included and in what their generation notebooks do by default.

Open the notebook guide →

Inference has several levels

Model-assisted interpretation is optional and builds on the corpus measurements. These levels describe different work:

  1. Corpus measurements: Doc4CF reads the TF features and computes coverage, values, node and edge counts, rendering information, and graph links. This is deterministic and runs offline.
  2. Dataset context: a model summarizes corpus-wide conventions, scope, and open questions from the measured inventory and supplied editorial guidance.
  3. Feature families and relationships: a model proposes feature groupings and links, with evidence paths and review status.
  4. Feature descriptions: a model writes explanatory prose for selected features. With context artifacts enabled, each request can use relevant dataset, family, and relationship context.
  5. Targeted evidence: an optional planning request can ask Doc4CF to retrieve rare values or examples before the final feature-description request. This adds requests and is disabled by default in these notebooks.

These levels are not a single quality score. A site may have complete measured feature pages while only some features have generated prose.

How to read the comparison

The model-generated-description counts above are measured from the checked-in feature pages. N1904 was refreshed with context-aware enrichment and Markdown export; DSS remains a measured, model-free example, and Old Babylonian retains its existing generated descriptions. Complete page coverage and complete model coverage are separate measurements.

Notebook settings describe the next build and can differ from the snapshots now checked in. Enabling inference may add dataset, relationship, and feature descriptions; cache contents, corpus revision, model availability, and saved context artifacts determine whether that run makes requests or reuses prior responses.

For a reproducible rebuild, review the notebook settings and the corpus revision before enabling publication. The notebook guide explains the cache, model, API-key, and publishing controls for all three examples.
